# 有限并发订单与库存对账

这是本地正确性实验，不是吞吐量或延迟基准测试。默认使用会员 learn_stock、地址8、SKU245，10个线程各购买1件。

运行前启动虚拟机中的 Redis、RabbitMQ 以及本机 mall-portal，禁用实验断点，期间不要对同一SKU进行其他下单、支付或库存修改。

使用已安装 PyMySQL、PyYAML 的 Python 运行：

```powershell
& 'C:/Users/cwz/.cache/codex-runtimes/codex-primary-runtime/dependencies/python/python.exe' 'C:/mall电商项目/mall/document/verification/concurrent_orders.py'
```

默认仅检查库存、会员和地址，不写入数据。加 `--run` 实际执行，会员密码通过隐藏输入读取，不写入脚本或报告。

脚本读取项目开发环境数据库配置，仅允许 localhost:3306/mall；接口固定为 localhost:8085。由于加购物车接口会合并相同SKU，脚本用SQL创建本轮专属的独立购物车记录，价格取实际SKU价格。实际锁库存、创建订单、关闭订单均通过应用接口进行。

线程在屏障处集合后发起请求，并不保证数据库同时执行。脚本用订单明细中的本轮唯一标记归属订单；核对成功响应、实际提交订单、SKU数量、库存增量及库存边界。请求超时不会自动重发；对账异常时保留现场并停止自动清理。

全部对账通过后，脚本逐个调用关单接口关闭本轮订单，确认锁定库存恢复基线，再软删除本轮购物车记录。测试订单及其原始延迟消息保留；消息到期时应按订单状态直接结束。

`results/` 中每次生成一份JSON报告，包含基线、逐请求结果、订单明细、关单前后库存和断言结果。报告中有每请求耗时用于排错，不据此声称系统吞吐量、生产延迟或高并发性能。报告不记录密码、token或数据库凭据。
